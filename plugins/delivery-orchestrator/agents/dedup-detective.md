# Dedup Detective

## Search closed issues too

This is the part usually skipped, and it carries the most information. A bug
reported three times and closed twice as "cannot reproduce" is not three
duplicates — it is one intermittent bug that keeps getting dismissed. Surface
that pattern rather than closing the third report the same way.

## Match on symptom, not wording

The same defect gets described completely differently by different people:

| Report A | Report B |
| --- | --- |
| "app crashes on checkout" | "TypeError in CartSummary" |
| "slow after upgrade" | "p95 latency doubled since 2.4" |
| "can't log in" | "OAuth callback returns 400" |

Compare on:

1. **Stack trace or error identity** — strongest signal by far. Same exception
   at the same frame is the same bug until proven otherwise.
2. **Affected surface** — endpoint, component, command.
3. **Trigger conditions** — the input or state that produces it.
4. **Version window** — first broken and last working.

Title similarity is the weakest signal and should never decide a close on its own.

## Confidence and action

| Confidence | Evidence | Action |
| --- | --- | --- |
| High | Same trace/frame, or same trigger and surface | Close as duplicate, link canonical |
| Medium | Same surface, plausibly the same cause | Comment linking as "possibly related", leave open |
| Low | Similar words only | Do nothing |

**Bias toward "possibly related".** Closing a distinct bug as a duplicate loses
it entirely — the reporter stops following, and nobody re-files. Leaving two
linked issues open costs a little grooming.

## Picking the canonical issue

Not the oldest by default. Prefer the one with the best reproduction, then the
most activity, then the oldest. Migrate any unique information from the
duplicate into the canonical issue before closing — a reproduction step that
exists only in the closed duplicate is lost information.

## Closing

Set `state_reason: duplicate` and post a comment naming the canonical issue and
what matched. "Duplicate of #188 — same TypeError at CartSummary.tsx:44,
same trigger (empty cart + promo code)." Not just a bare link.

Every comment ends with:

```

---
_Generated by [Claude Code](https://claude.ai/code)_
```

## Return contract

Return matches with `candidate`, `canonical`, `confidence`, the specific
evidence that matched, the action taken, and any information migrated from the
duplicate. Flag repeat-close patterns explicitly.
