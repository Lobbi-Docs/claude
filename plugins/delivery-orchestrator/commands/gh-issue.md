# /gh:issue

## Usage

```
/gh:issue create "ingest drops events above 10k/s"
/gh:issue create --from-failure 1849302     # from a CI failure
/gh:issue create --from-finding             # from a review-board finding
/gh:issue update 214 --label bug,ingest --assignee alice
/gh:issue close 214 --reason completed
/gh:issue link 214 --pr 482                 # closes-with relationship
/gh:issue sub 214 --add 215,216,217         # parent/sub-issue
```

## Creating

Before creating, **search first** — `mcp__github__search_issues` across open and
closed. Duplicating an existing issue is worse than not filing one.

Check `mcp__github__list_issue_types` for organizations that define issue types,
and use the repository's issue template if one exists
(`.github/ISSUE_TEMPLATE/`).

A well-formed bug body has, in this order:

1. **What happens** — one sentence, observable.
2. **Reproduction** — exact steps or the command that triggers it.
3. **Expected vs actual.**
4. **Evidence** — stack trace, log excerpt, run id, `file:line`.
5. **Environment** — version, platform, config that matters.
6. **Scope** — what is and is not affected.

Feature issues replace 1–3 with **problem**, **proposed behavior**, and
**why now**.

### `--from-failure`

Builds the body from a CI run: failing job, log excerpt, the commit range that
introduced it (via bisect over recent runs where available), and the affected
test names. Used by `flake-detective` when quarantining.

### `--from-finding`

Builds the body from a surviving review-board finding: the defect, the failure
scenario, `file:line`, and the verifier verdicts that let it through.

## Closing

Always set `state_reason` — `completed`, `not_planned`, or `duplicate`. An issue
closed without a reason loses the information that made closing correct.

Closing as duplicate posts the link to the canonical issue in the same call.

## Linking

| Relationship | Mechanism |
| --- | --- |
| PR closes issue | `Closes #214` in the PR body — the only form GitHub auto-links |
| Issue → parent epic | `mcp__github__sub_issue_write` |
| Related, not blocking | A comment with the link and one sentence of why |
| Blocked by | Label `blocked` plus a comment naming the blocker |

Do not write `Closes #214` in a commit message when the PR body already has it —
that double-links and closes on the wrong event for squash merges.

## Never in an issue body

Credentials, tokens, environment variable values, internal hostnames, customer
identifiers, or unredacted stack traces from production containing PII. If a log
excerpt carries any of these, redact before filing.
